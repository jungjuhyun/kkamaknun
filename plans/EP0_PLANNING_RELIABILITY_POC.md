# 현재 실행 계획 — 0화 YouTube 기획 실행 신뢰성 POC

상태: **ACTIVE**
기준일: 2026-09-02

이 문서는 이번 **`0화 YouTube 기획 실행 신뢰성 POC` 전용 실행 문서**다.
- 다른 프로젝트 계획을 이 문서에 덧붙이지 않는다.
- 이후 새로운 계획의 공용 `CURRENT_PLAN` 파일로 재사용하지 않는다.
- 이번 POC가 종료되면 이 문서의 ACTIVE 실행 문서 역할도 종료한다.
- POC 종료 후 장기적으로 남길 결과만 적절한 owner/`STATE.md`에 반영하고, 이 일회성 문서의 정리 여부는 그때 별도로 판단한다.

이 문서는 현재 작업의 **실행 체크리스트**다. 아래 순서를 임의로 건너뛰지 않는다. 각 단계가 끝날 때 체크 상태를 갱신하고 다음 단계로 이동한다.

## 목표

이번 POC에서 증명할 것은 하나다.

> **repo의 current truth와 기획 공정을 실제 실행 단계에서 유지하면서, 현재 확보 가능한 근거와 검증된 콘텐츠 원칙을 활용해 `유튜브라는 플랫폼에서의 성공 확률`을 최대한 높인 0화 촬영 전 가상 완성본을 만들 수 있는가.**

여기서 `유튜브라는 플랫폼에서의 성공 확률`은 결과 보장이 아니라 다음을 동시에 높이는 방향의 기획을 뜻한다.

- 노출됐을 때 선택될 이유
- 클릭 후 계속 볼 이유
- 시청 후 만족과 기억에 남을 이유
- 채널과 인물에 대한 후속 시청·구독 이유
- 장기적으로 반복 가능한 채널 경쟁력

단순히 오류가 없는 것도 부족하고, 단순히 촬영 가능한 초안만 나와도 부족하다. **current truth 준수 + YouTube 경쟁력을 고려한 기획 품질**을 둘 다 통과해야 한다.

---

## 실행 원칙

- repo current owner가 사실 기준이다.
- 실제로 확보하지 않은 자료를 확보했다고 하지 않는다.
- 가상 완성본의 사건·성공·실패·반응은 촬영 전 시뮬레이션으로 적극적으로 설정할 수 있지만 실제 촬영 사실로 승격하지 않는다.
- 큰 공정은 `목표 잠금 → 원안 → RED TEAM → 수리 → 한 번 재공격 → 실행 → 실제 결과로 교정`을 따른다.
- 실행강제 시스템을 먼저 크게 만들지 않는다. 이 수동 POC에서 실제 실패 유형을 확인한 뒤 필요한 부분만 자동화한다.
- 아래 체크리스트의 미완료 선행 단계를 건너뛰지 않는다.

# 세부 계획

## 1. 이번 작업의 RUN CONTRACT 잠금

새 규칙을 만드는 것이 아니라 `STATE.md + FIRST_VIDEO.md + PLAYBOOK.md`에서 이번 0화 작업에 필요한 것만 추출해 작업 계약으로 고정한다.

### LOCKED — 변경 금지

- A: `20년 이상 애니를 봤지만 일본어를 제대로 공부해본 적은 없는 사람`
- B: `체인소 맨: 레제편을 한국어 자막 없이 보고, 자기 귀에 실제로 무엇이 남아 있는지 확인한다.`
- C: `FIRST_VIDEO.md`의 현재 3층 감상 구조
- 레제편으로 실제 테스트 촬영이 진행되었다는 사실
- 1차 약 82분 촬영물이 이미 존재한다는 사실
- 0화 진단용 촬영 프로토콜이 이미 채택됐다는 사실

### AVAILABLE — 실제 확인된 자료

- 현재 repo owner 문서
- 현재 owner에 기록된 청해 관찰과 사전 검증 결과
- 기존 촬영물의 존재와 현재 기록된 촬영 상태

### UNAVAILABLE — 있다고 주장하면 HARD FAIL

- 실제로 확보하지 못한 레제편 일본어 전체 자막 본문
- 실제로 확인하지 않은 특정 촬영 장면의 구체 내용
- 아직 검증되지 않은 최종 촬영 반응이나 결과

### SIMULATION ALLOWED

촬영 전 가상 완성본을 위해 다음은 적극적으로 가정할 수 있다.

- 특정 장면에서 정확히 알아듣는 사건
- 부분적으로 알아듣는 사건
- 뜻은 이해하지만 정확한 소리를 못 잡는 사건
- 소리는 잡지만 실제 표기·어휘 형태를 모르는 사건
- 문맥 때문에 자신 있게 오해하는 사건
- 예상보다 어려운 대사를 맞히는 사건
- 웃음·당황·확신·번복 등의 반응
- 사건의 순서와 영상 내 배치

이것들은 **촬영 전 시뮬레이션**이며 실제 프로젝트 사실이 아니다.

## 2. 기획 목표 잠금

이번 작업의 목표는 `영상으로 만들 수 있는 0화`가 아니다.

> **현재 확보 가능한 근거와 검증된 콘텐츠 원칙을 활용해서, 유튜브라는 플랫폼에서 선택·시청지속·만족·후속 시청/구독 가능성을 최대한 높이는 0화 촬영 전 가상 완성본을 만든다.**

### 기획 HARD GOALS

- 클릭할 이유가 있어야 한다.
- 초반부터 계속 볼 이유가 있어야 한다.
- 중간에 계속 볼 이유가 갱신되어야 한다.
- A+B가 실제 사건을 특별하게 만들어야 한다.
- C가 마지막 설명이 아니라 시청 경험에서 발생해야 한다.
- 영상 전체가 향하는 콘텐츠 각이 있어야 한다.
- 사용자라는 인물이 사건·판단·실수·발견 속에서 드러나야 한다.
- 다 본 뒤 다음 영상을 보고 싶은 이유가 남아야 한다.
- 화면이 이미 말하는 내용을 나레이션이 중복 설명하지 않아야 한다.
- `일본어 청해 테스트 사례 모음`의 단순 반복으로 끝나면 안 된다.
- 조회수 보장이나 알고리즘 선택 보장을 주장하지 않되, YouTube에서 경쟁력이 높아지도록 조사·구조·패키징·시청 흐름을 설계한다.

## 3. 0화 가상 완성본 1차 작성

`[촬영 후 결정]`, `[좋은 장면이 나오면]`, `[실제 반응이 있다면]` 같은 빈칸형 기획을 사용하지 않는다.

가상 촬영본이 이미 존재한다고 가정하고 처음부터 끝까지 구체적으로 작성한다.

기본 출력 형식:

| 클립화면 | 나레이션 |
|---|---|
| 실제로 어떤 화면이 보이는지 구체적으로 | 현장음·나레이션·무음 중 실제 들어갈 내용을 구체적으로 |

- 성공/실패/부분 이해/오해/반응을 AI가 구체적으로 설정한다.
- 목적은 실제 결과 예측이 아니라 촬영 전에 어떤 사건과 반응이 영상 재료가 되는지 시뮬레이션하는 것이다.

---

## 4. 사용자에게 공개하기 전 HARD VALIDATION

이 단계에서는 재미를 평가하지 않는다. current truth 위반과 명백한 사실 오류만 검사한다.

다음 중 하나라도 있으면 **HARD FAIL**이며 RED TEAM으로 넘어가지 않는다.

- A/B/C 임의 변경
- 자막 본문을 실제 확보했다고 허위 주장
- 가상 장면을 실제 촬영 사실로 서술
- 이미 존재하는 촬영물이 없다고 서술
- 채택된 촬영 프로토콜을 새 제안처럼 변경
- 실제 자료보다 강한 사실 주장
- current owner와 충돌
- 현재 요청과 무관한 1화·장면 수집기 등으로 이탈

FAIL이면 해당 오류를 고친 뒤 HARD VALIDATION을 다시 통과해야 한다.

## 5. 기획 RED TEAM #1

HARD PASS 후 초안을 처음 보는 경쟁 영상처럼 공격한다.

### 시청자 견인

- 제목/썸네일을 봤다고 가정했을 때 왜 클릭하는가?
- 첫 장면부터 왜 계속 보는가?
- 각 주요 장면 뒤에 `다음은 왜 보지?`에 답이 있는가?
- 결과 범위가 너무 예상 가능하지 않은가?
- 같은 기능의 사례가 반복되지 않는가?

### ABC / 콘텐츠 각

- A의 맥락이 자기소개가 아니라 사건을 특별하게 만드는가?
- B가 단순 행동이 아니라 사건을 발생시키는가?
- A+B가 이 영상만의 힘을 만드는가?
- C가 마지막 설명 때문에 생기는 게 아니라 영상을 보는 동안 발생하는가?
- 영상 전체가 가장 강한 콘텐츠 각을 향해 가는가?

### YouTube 플랫폼 경쟁력

- 제목/썸네일의 약속과 실제 첫 구간이 맞물리는가?
- 초반 이후 시청 이유가 한 가지 결과 공개에만 의존하지 않는가?
- 장면마다 시청자의 판단·기대·의문이 바뀌는가?
- 불필요한 설명과 동일 기능 반복 때문에 이탈 구간이 생기지 않는가?
- 영상 종료 후 다음 콘텐츠를 볼 이유가 자연스럽게 남는가?

### 사람 / 구독

- 영상 주제보다 사용자라는 사람이 기억되는가?
- 선택·오판·발견·반응이 실제 인물성을 드러내는가?
- `다음에 이 사람이 무엇을 할까?`라는 궁금증이 생기는가?

### 화면

- 화면으로 이미 알 수 있는데 다시 설명하는 나레이션이 없는가?
- 정보 설명보다 사건을 직접 보여주는가?
- 구조표만 읽어도 머릿속에서 실제 영상이 재생되는가?

## 6. RED TEAM 결과를 PASS / WEAK / FAIL로 판정

예:

```text
사실/가정 경계: PASS
A/B 유지: PASS
초반 견인: FAIL
중간 엔진: FAIL
C: PASS
콘텐츠 각: WEAK
구독 이유: FAIL
화면 시각화: PASS
```

`FAIL`이나 핵심 `WEAK`가 있으면 완성본으로 공개하지 않는다.

---

## 7. FAIL / WEAK 항목만 수리

전체 기획을 습관적으로 처음부터 다시 만들지 않는다.

- 실패한 기능만 수정한다.
- 수정 후 다시 HARD VALIDATION을 통과한다.
- 그다음 RED TEAM #2를 수행한다.

## 9. 사용자에게 최종안 공개

이번 POC에서는 신뢰 검증을 위해 다음 3가지를 함께 공개한다.

### A. 최종 가상 완성본

`클립화면 | 나레이션` 중심.

### B. 최종 기획 잠금

짧게 확인:

- A
- B
- 왜 봐야 하는가
- C
- 콘텐츠 각
- 다음 편을 볼 이유

### C. 검증 결과

- HARD CHECK 결과
- RED TEAM #1 결과
- 수정한 지점
- RED TEAM #2 결과

POC가 안정화된 뒤에는 매번 이 검수 로그 전체를 사용자에게 보여줄 필요는 없다.

## 10. 사용자 품질 판정

사용자가 판단할 핵심은 내부 오류 검수가 아니다.

- `이거 실제로 찍어보고 싶은가?`
- `내가 시청자라도 계속 볼 것 같은가?`

판정 분리:

- 공정 오류가 남음 → 실행 신뢰성 실패
- 공정은 지켰지만 영상이 평범함 → 기획 품질 실패
- 둘 다 통과 → 다음 단계 진행

### 진행 중 판정 — 패키징

- 제목·썸네일 / 패키징: **FAIL**
- 사용자는 현재 패키지를 실제로 사용하고 싶지 않다고 판정했다.
- AI 내부 `RED TEAM #2`에서는 패키징을 PASS로 판정했지만, 실제 사용자 품질 판정에서는 FAIL했다.
- 이 차이는 이번 POC의 **기획 품질 실패**로 기록한다.
- 본편 구조는 패키징과 분리해 아직 판정하지 않는다. 패키징 FAIL만으로 본편 전체를 FAIL 처리하지 않는다.
- 10번은 진행 중 상태로 유지하고, 본편 구조에 대한 사용자 품질 판정을 받은 뒤 완료 여부를 결정한다.
- 11번·12번으로는 아직 진행하지 않는다.

## 11. 새 채팅 복원 시험

중요 checkpoint가 repo에 반영된 뒤 새 채팅에서 bootstrap을 수행한다.

새 채팅에서 사용자가 프로젝트 맥락을 다시 설명하지 않고도 AI가 다음을 복원해야 한다.

- 현재 POC 목적
- locked A/B/C
- 가상 완성본의 의미
- 기존 실제 촬영물이 존재한다는 사실
- 확보하지 못한 자료를 확보했다고 하지 않아야 한다는 상태
- 현재 체크리스트 단계

사용자가 핵심 맥락을 다시 설명해야 하면 **복원 실패**로 판정한다.

## 12. 자동 runner 구현 여부 결정

이 수동 POC 결과 뒤에만 결정한다.

### 결과 A — 수동 체크리스트만으로 충분히 안정적

runner를 만들지 않는다.

### 결과 B — 기획 품질은 충분하지만 hard error가 반복

`locked run state + deterministic validator`부터 최소 자동화한다.

### 결과 C — hard error는 없어졌지만 기획 자체가 계속 평범함

runner 문제가 아니다. 기획 모델·외부 조사·평가 rubric·모델 선택 문제를 다시 본다.

특정 framework나 다중 agent 구조를 미리 고정하지 않는다.
