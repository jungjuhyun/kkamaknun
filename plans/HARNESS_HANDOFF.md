## 1. 목표

규칙이 문서에만 있고 실제 답변에서 안 지켜지는 문제를 막는다.
문서(설계도)는 이미 다 있다. 없는 것은 규칙을 어겼을 때 걸리는 장치다.

한 줄: **규칙은 고치고, 장치는 만들되, 장치가 읽는 것은 고친 규칙이다.**

사용자가 가장 싫어하는 것: 규칙과 파일이 덕지덕지 붙어 누더기가 되어 실행이 안 되는 상태.
그래서 이번 작업의 첫 규칙은 **옮긴 규칙은 원래 자리에서 지운다**이다.

## 2. 역할

| 누가 | 무엇을 |
|---|---|
| 사용자 | 방향 결정, 내용 승인, 최종 판정. 내부 구조·분류·기술 선택은 하지 않는다. |
| Claude Code (이 문서를 읽는 쪽) | 파일 수정, 코드 작성, 브랜치에 커밋·푸시 |
| Claude 채팅 (관제) | 결과를 저장소에서 읽고 검수. 올리지 않는다. |

Claude Code는 저장소 안에서 자유롭게 고친다. 다만 **main에는 직접 커밋하지 않는다.** harness 브랜치에만 올린다.

- 재미·구조 품질을 기계로 판정하려는 시도. 그건 사용자 몫이다.
- main 직접 수정.
- 사용자에게 분류·구조·기술 선택을 묻기.
